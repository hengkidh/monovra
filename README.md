# MONOVRA

**Less interface. More drive.**

MONOVRA is a lightweight, minimalist **Android Home launcher** for aftermarket
Android car head units. Black, white and gray form the foundation, Indigo
(`#4F46E5`) marks interaction, and album artwork is the only strong color.

- Real Android launcher (`CATEGORY_HOME`), selectable as the default Home app
- Three-part dashboard: swipeable clock on the left, music player in the center, and a vertical shortcut rail on the right
- Live music from Android media sessions (YouTube Music first, Spotify and others work too)
- Full-screen Focus Mode: swipe up from Home to enter, swipe down to return, and swipe horizontally across four clock/player layouts, including an edge-to-edge ambient layout over blurred album art
- Three theme modes, switched instantly from the dock or **Settings › Appearance**: **Dark** (true black), **Light** (pure white) and **Auto**, which follows Android's day/night (dark mode) setting
- A calm idle state when nothing is playing, with one-tap buttons for the installed music apps
- Grayscale app icons, full-color album art
- Works fully offline: no INTERNET permission, no backend, no analytics

> Application ID: `id.hengki.monovra` · Android 10+ (API 29) · landscape-first (1024×600, 1280×720 and others)

## 1. Download the APK

Release builds are published on the repository's **GitHub Releases** page
(`monovra-vX.Y.Z.apk` plus a `.sha256` checksum). Every push also builds a debug
APK, downloadable from the **Actions** tab › *CI* › run › *Artifacts*.

## 2. Install on a head unit

1. Copy the APK to the head unit (USB stick or download it in the unit's browser) and open it.
   Allow "Install unknown apps" for the file manager or browser if asked.
2. Open **MONOVRA**.
3. **Settings › Music › Open permission settings** and enable Notification Access for MONOVRA
   (needed to show and control music, see [§12](#12-permissions-and-firmware-limitations)).
4. **Settings › Launcher › Set MONOVRA as Default Launcher**, then confirm in the Android dialog.
5. Press the Home button: MONOVRA opens.

To go back to the factory launcher: **Settings › Launcher › Open Android Home Settings** and pick it,
or Android **Settings › Apps › Default apps › Home app**.

## 4. Development with Docker

Only **Docker** (with Compose) is required on your machine. No JDK, Android SDK or Node install.

### 4.1 One-time setup

```bash
make image
```

This builds `monovra-builder` (≈2 GB: JDK 17, Android SDK platform 35, build-tools 35, Node). Gradle 8.11.1 is downloaded by `android/gradlew` on the first build (checksum-verified) and kept in the `gradle_cache` volume.

> **Apple Silicon (M1/M2/M3…)**: Google ships Linux build-tools for x86_64 only, so the builder
> image is `linux/amd64`. With Colima, enable Rosetta for fast emulation and give the VM ≥4 GB RAM:
>
> ```bash
> colima start --cpu 4 --memory 4 --vz-rosetta
> ```
>
> Docker Desktop: enable *Use Rosetta for x86_64/amd64 emulation* in Settings › General.

### 4.2 Frontend dev server (UI work in the browser)

```bash
make web
```

Open <http://localhost:5173>. Outside Android a **mock bridge** provides sample apps and a sample
track so the layout can be designed in a desktop browser. Use the device toolbar at 1024×600 or
1280×720. Query options:

| URL | Shows |
| --- | --- |
| `/?music=playing` | a playing track (default) |
| `/?music=empty`   | idle state ("Nothing playing" + music-app buttons) |
| `/?music=denied`  | Notification Access onboarding |
| `/?theme=white` / `black` / `auto` | start in a theme (`auto` follows the browser's color scheme) |

The mock exists only in `vite dev`; production builds never contain it.

### 4.3 Build the APK

```bash
make apk        # → dist/monovra-debug.apk   (application id id.hengki.monovra.debug)
make release    # → dist/monovra-release.apk (id.hengki.monovra)
```

Both run `scripts/build.sh` inside the builder: `npm ci && vite build` (output to
`android/app/src/main/assets/web`) then Gradle. The Gradle cache lives in a Docker volume, so
later builds are much faster.

The debug build uses the `.debug` suffix, so it can be installed next to a release build.

### 4.4 Other commands

```bash
make shell      # bash inside the builder (sdkmanager, node; run ./gradlew in android/)
make wrapper    # regenerate android/gradlew + wrapper jar
make clean      # remove build outputs
```

Equivalent raw commands:

```bash
docker compose up web
docker compose run --rm builder scripts/build.sh debug
docker compose run --rm builder bash
```

## 5. Building without Docker / Android Studio

Requirements: JDK 17, Android SDK (platform 35, build-tools 35), Node 20+.

```bash
cd frontend && npm ci && npm run build && cd ..
cd android && ./gradlew assembleDebug
```

**Android Studio**: *Open* the `android/` folder. Build the frontend once first (above);
Gradle stops with a clear message if `assets/web/index.html` is missing. After changing frontend
code, run `npm run build` again before *Run*.

## 6. Signed release APK

Create a keystore once and keep it safe (losing it means users must uninstall to update):

```bash
mkdir -p keys
keytool -genkeypair -v -keystore keys/monovra-release.jks -alias monovra \
  -keyalg RSA -keysize 4096 -validity 10000
```

(`keytool` is also available inside the builder: `make shell`.) `keys/` and `*.jks` are git-ignored.

Then:

```bash
cp .env.example .env    # fill in the passwords; .env is git-ignored
make release
```

Signing is configured from environment variables:

| Variable | Meaning |
| --- | --- |
| `MONOVRA_KEYSTORE_FILE` | path to the `.jks` (inside Docker: `/workspace/keys/…`) |
| `MONOVRA_KEYSTORE_PASSWORD` | keystore password |
| `MONOVRA_KEY_ALIAS` | key alias |
| `MONOVRA_KEY_PASSWORD` | key password |
| `MONOVRA_VERSION_NAME` / `MONOVRA_VERSION_CODE` | optional version override |

If no keystore is configured, a **local** release build is signed with the **debug key** and Gradle
prints a warning. That APK installs fine but is not suitable for public distribution. The GitHub
**Release APK** workflow never does this: it stops with an error if any of the four secrets in §7 is
missing, because a CI debug key changes on every run and users could never update in place.

Verify a signed APK:

```bash
docker compose run --rm builder bash -c '$ANDROID_HOME/build-tools/35.0.0/apksigner verify --print-certs dist/monovra-release.apk'
```

## 7. Publishing APKs on GitHub

Two workflows are included:

- **CI** (`.github/workflows/ci.yml`): every push / PR builds the debug APK and lint,
  and uploads the APK as a workflow artifact (14 days).
- **Release APK** (`.github/workflows/release.yml`): pushing a tag `v*` builds a signed
  release APK and attaches `monovra-vX.Y.Z.apk` + `.sha256` to a GitHub Release.

One-time setup, in the repository's **Settings › Secrets and variables › Actions**:

| Secret | Value |
| --- | --- |
| `MONOVRA_KEYSTORE_BASE64` | `base64 -i keys/monovra-release.jks` (macOS) or `base64 -w0 …` (Linux) |
| `MONOVRA_KEYSTORE_PASSWORD` | keystore password |
| `MONOVRA_KEY_ALIAS` | `monovra` |
| `MONOVRA_KEY_PASSWORD` | key password |

Publish a version:

```bash
git tag v0.1.0
git push origin v0.1.0
```

The version name comes from the tag; the version code is `100 + workflow run number`, so it always
increases. You can also start the workflow manually (*Actions › Release APK › Run workflow*).

## 8. ADB debugging

Install platform-tools on the host (`brew install android-platform-tools` on macOS), or use `adb`
from the builder container over Wi-Fi.

**Connect**

```bash
adb devices                       # USB (enable Developer options › USB debugging on the unit)
adb connect 192.168.1.50:5555     # Wi-Fi ADB, if the head unit supports it
```

**Install and run**

```bash
make install                                         # adb install -r dist/monovra-debug.apk
adb shell am start -n id.hengki.monovra.debug/id.hengki.monovra.MainActivity
adb shell am start -a android.intent.action.MAIN -c android.intent.category.HOME   # press "Home"
```

**Logs**

```bash
make logcat                       # adb logcat -s Monovra:* chromium:*
```

**Inspect the WebView** (debug builds): open `chrome://inspect/#devices` in desktop Chrome while
the unit is connected; MONOVRA's page appears under *WebView in id.hengki.monovra.debug*.

**Permissions and roles**

```bash
# Grant Notification Access without the Settings UI (debug/testing):
adb shell cmd notification allow_listener \
  id.hengki.monovra.debug/id.hengki.monovra.media.MediaNotificationListener

# Make MONOVRA the Home app / restore another launcher:
adb shell cmd role add-role-holder android.app.role.HOME id.hengki.monovra.debug
adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN

# Inspect media sessions:
adb shell dumpsys media_session
```

**Sleep / wake test**

```bash
adb shell input keyevent KEYCODE_SLEEP
adb shell input keyevent KEYCODE_WAKEUP
```

## 9. Architecture

```
┌──────────── Android (Kotlin) ────────────┐        ┌────────── WebView (JS) ──────────┐
│ AppRepository   PackageManager + package │        │ main.js   boot, events → store   │
│                 broadcasts (no polling)  │ events │ store.js  tiny reactive state    │
│ MediaRepository MediaSessionManager +    ├───────►│ ui/*      clock, apps, music,    │
│                 MediaController callbacks│        │           focus, dock, settings  │
│ SettingsRepo    Jetpack DataStore        │◄───────┤ bridge.js request/response       │
│ SystemActions   RoleManager, Settings    │ calls  │ styles.css Tailwind v4 + tokens  │
│ NativeBridge    validation, dispatch     │        └──────────────────────────────────┘
│ WebViewAssetLoader                       │
│   /assets/web/*  bundled UI              │   https://appassets.androidplatform.net
│   /icon/<pkg>.png  app icons (cached)    │   (served locally, never from network)
│   /art/<token>.jpg current album art     │
└──────────────────────────────────────────┘
```

- **One WebView**, one page. All assets are bundled in the APK and served by
  `WebViewAssetLoader` on `https://appassets.androidplatform.net`. Network loads are blocked and
  the app has no INTERNET permission.
- **Kotlin owns Android integration**; the frontend is pure UI. No frameworks: vanilla ES modules,
  Tailwind compiled at build time, Lucide icons tree-shaken (only the icons used are bundled).
- **Themes**: CSS custom properties under `html[data-theme]` (`black` or `white`). The stored
  preference is `black`, `white` or `auto`; a tap swaps the attribute (instant, no reload) and Kotlin
  persists the preference in DataStore. `auto` resolves from Android's night mode: Kotlin handles
  `uiMode` in `onConfigurationChanged`, repaints the window and system bars, and pushes a `system`
  event with `nightMode` so the page switches too, without recreating the activity. On launch Kotlin
  resolves the theme before creating the WebView, paints the window in that color and passes
  `?theme=` to the page, where `theme-boot.js` applies it before the first paint, so there's no
  flash of the wrong theme.
- **Clock**: the analog second hand and the seconds bar sweep with CSS animations. A once-per-second
  ticker compares the wall clock with the monotonic clock and re-aligns the sweeps whenever they
  disagree (head-unit sleep, GPS/NTP time correction). The second hand has a single driver, the CSS
  sweep, or a stepped transform when reduced motion is on, so older WebViews never paint a doubled hand.
- **Icons** come from `PackageManager`, rendered to 144 px PNGs, cached in an LRU (3 MB) and shown
  grayscale with CSS `filter: grayscale(100%)`. Album art is never filtered.
- **Music**: `MediaSessionManager.getActiveSessions()` (allowed by the notification listener
  component) + `OnActiveSessionsChangedListener` + `MediaController.Callback` on each session.
  Selection: playing sessions first; then the preferred app, YouTube Music, the previous session.
  Artwork comes from `ALBUM_ART`/`ART`/`DISPLAY_ICON` bitmaps or, if there's none,
  `ALBUM_ART_URI`/`ART_URI` (only `content://` and `android.resource://`). It is resized to 512 px,
  stored as a JPEG and exposed as an opaque `/art/<token>.jpg`; only the current token resolves.
  Progress is interpolated in JS from `positionMs`, `capturedAt` and `speed`, updating once per
  second while playing and visible, and stops when paused.
- **Lifecycle**: media listeners register in `onStart` and unregister in `onStop`; WebView timers
  pause in `onStop` (covers head-unit sleep). If the WebView renderer is killed under memory
  pressure, the activity rebuilds it instead of crashing. Back and Home never close the launcher;
  they return the UI to the dashboard.

## 10. Kotlin ↔ JavaScript bridge

Transport: `WebViewCompat.addWebMessageListener` registered as `window.MonovraNative` and
**restricted to the origin `https://appassets.androidplatform.net`, main frame only**. Pages from
any other origin never see the object. On WebViews without that feature a
`@JavascriptInterface` fallback is used, and it rejects calls unless the committed page is the
trusted origin. Navigation away from the bundled page is blocked either way.

```jsonc
// JS → Kotlin
{ "id": 7, "method": "launchApp", "params": { "packageName": "com.waze" } }

// Kotlin → JS (response)
{ "type": "response", "id": 7, "ok": true, "result": { "launched": "com.waze" } }
{ "type": "response", "id": 7, "ok": false, "error": { "code": "NOT_INSTALLED", "message": "App is not installed" } }

// Kotlin → JS (pushed event; no polling)
{ "type": "event", "event": "music", "data": { /* MusicState */ } }
```

| Method | Params | Result |
| --- | --- | --- |
| `getBootstrap` | – | `{ device, settings, apps, music, system }` |
| `getDeviceInfo` | – | manufacturer, model, androidVersion, sdkInt, appVersion, webViewVersion |
| `getInstalledApps` | – | `App[]` |
| `getMusicState` | – | `MusicState` |
| `getSystemStatus` | – | `{ isDefaultLauncher, homeRoleAvailable, notificationAccess, sdkInt, nightMode }` |
| `launchApp` | `packageName` | `{ launched }` |
| `playPause` / `nextTrack` / `previousTrack` | – | `{ done }` |
| `openMusicApp` | `packageName?` | opens the session's player, else the preferred/YT Music/Spotify app |
| `setTheme` | `theme`: `black` \| `white` \| `auto` | `{ theme }` |
| `setFavorites` | `packages: string[]` (≤ 32, ordered) | `{ favorites }` |
| `setPreferredMusicApp` | `packageName \| null` | `{ preferredMusicApp }` |
| `requestHomeRole` | – | opens the RoleManager dialog (fallback: Home settings) |
| `openHomeSettings` / `openNotificationAccessSettings` / `openAppInfo` | – | `{ opened }` |

Events: `music`, `apps`, `settings`, `system`, `back`, `home`.

Data shapes:

```ts
App        = { packageName, label, icon: "/icon/<pkg>.png?v=…", isMusic, isNavigation }
MusicState = { permission: "granted"|"denied", hasSession, source: {packageName,label}|null,
               title, artist, album, artwork: "/art/<n>.jpg"|null,
               playback: "playing"|"paused"|"buffering"|"stopped"|"none",
               positionMs, durationMs /* -1 = unknown */, speed, capturedAt /* epoch ms */,
               actions: { playPause, next, previous } }
Settings   = { theme: "black"|"white"|"auto", favorites: string[], preferredMusicApp: string|null }
System     = { isDefaultLauncher, homeRoleAvailable, notificationAccess, sdkInt,
               nightMode /* Android dark mode, resolves the "auto" theme */ }
```

Validation: messages > 16 KB are dropped; method names are whitelisted; package names must match
the Java package pattern **and** be installed; favorites are capped and de-duplicated.
Error codes: `BAD_REQUEST`, `UNKNOWN_METHOD`, `INVALID_ARGUMENT`, `NOT_INSTALLED`, `LAUNCH_FAILED`,
`NO_SESSION`, `UNSUPPORTED`, `PERMISSION_DENIED`, `INTERNAL`.

## 11. Performance and profiling

Design choices for 2–4 GB head units: single WebView, no frameworks, no background or foreground
services, no polling (package broadcasts and media callbacks), one shared 1 s clock timer (paused when hidden; the second hand itself sweeps on the GPU)
and one per second for progress *only while playing and visible*, icons/artwork resized natively,
caches trimmed in `onTrimMemory`, release build minified with R8.

**RAM**

```bash
adb shell dumpsys meminfo id.hengki.monovra            # PSS of the app process
adb shell dumpsys meminfo | grep -i -A2 "sandboxed_process" # WebView renderer process
```

Compare idle on the dashboard, after opening All Apps, and after 10 minutes of playback.
Android Studio › *Profiler* › *Memory* gives the Java/native split.

**Startup**

```bash
adb shell am force-stop id.hengki.monovra
adb shell am start -W -n id.hengki.monovra/.MainActivity   # TotalTime = cold start
```

**Rendering / CPU**

- `chrome://inspect` › *Performance* tab: record while switching themes or tracks; there
  should be no recurring work while idle.
- `adb shell dumpsys gfxinfo id.hengki.monovra` for frame stats.
- `adb shell top -m 10 -s cpu` while the dashboard is idle: MONOVRA should be ~0%.

## 12. Permissions and firmware limitations

| Topic | Details |
| --- | --- |
| **Notification Access** | Required by Android to read media sessions of other apps. MONOVRA does not read notifications. Granted by the user in Settings. |
| **Android 13+ restricted settings** | For sideloaded APKs the Notification Access switch may be greyed out. Open *App info › ⋮ › Allow restricted settings*, then enable access. MONOVRA links to both screens. |
| **Default launcher** | Uses `RoleManager.ROLE_HOME` (Android 10+) with fallback to Home/Default-apps settings. Some head-unit firmwares hide these screens or force their own launcher on boot; MONOVRA cannot and will not bypass that. |
| **Vendor launchers** | Some units relaunch the factory launcher after sleep or reverse camera. Press Home again; MONOVRA never disables the factory launcher. |
| **Android System WebView** | The compiled CSS needs WebView **111+**. Older units show a warning with a link to update *Android System WebView* (Play Store or APK). |
| **Package visibility** | Uses `<queries>` for `MAIN/LAUNCHER` (and media browser services) instead of `QUERY_ALL_PACKAGES`. Vendor apps with a launcher entry are listed. |
| **Artwork** | Some players publish artwork only as `http(s)` URIs; MONOVRA has no network access, so those show the placeholder. YouTube Music and Spotify provide bitmaps. |
| **Playback controls** | Buttons are enabled only for actions the session reports. Some players report none. |
| **No root** | Nothing requires root, system signature or firmware changes. |

## 13. Testing checklist

- [ ] `make apk` succeeds; app opens on 1024×600 and 1280×720 (`adb shell wm size 1024x600`, `wm size reset`)
- [ ] Dark / Light / Auto in the dock switch instantly; the choice persists after `am force-stop` with no flash on launch
- [ ] Auto follows day/night: `adb shell cmd uimode night yes` / `night no` switches the page and system bars without a restart
- [ ] Analog second hand: one hand only, matches the digital seconds, and is still aligned after sleep/wake
- [ ] Focus Mode swipes between clock-only, split player, centered compact player, and ambient artwork layouts; the ambient artwork fills the screen edge to edge with the clock centered
- [ ] Swipe up from Home opens Focus Mode; swipe down from Focus returns Home without disrupting horizontal page swipes
- [ ] Shortcuts open apps; All Apps search; pin/unpin; reorder in Settings › Applications
- [ ] Install and uninstall an app while MONOVRA is open: the lists update
- [ ] Without Notification Access → onboarding; after granting → music appears without restarting
- [ ] YouTube Music: title/artist/art/progress, play/pause/next/prev, tap art opens the player
- [ ] Pause stops progress; skipping resyncs; no music → "Nothing playing" with buttons for the installed music apps
- [ ] Set as default launcher; Home button returns to the dashboard; Back closes panels only
- [ ] Sleep/wake (`KEYCODE_SLEEP` / `KEYCODE_WAKEUP`) restores state and music
- [ ] Idle CPU ≈ 0% and memory stable over a long drive
